ROYAL VOID — EIGHT THEMES

This update adds Dark / Royal Void, Fire, Thunder, Water, Earth, Diamond, Gold and Spirit.
Theme selection is in Command centre, above backup and interface settings.
The choice changes all menu surfaces and controls, persists locally, and is exported/restored with interface settings.
Theme switching makes no HTTP requests. Owner configuration is read once at launch with branding.
The previous NativePayloadLoader game boot-order fix and launcher outline removal are included.

INSTALL THE JAVA UPDATE
Replace the matching Java files in:
/storage/emulated/0/Dynamons/RoyalVoid/src/com/dynamongamer/royalvoid/
Add the NEW ThemeManager.java there too. Replace all twelve files together.
Use your saved Termux commands to rebuild. No DEX is prebuilt by this update.
Replace only the Royal Void DEX in the game APK, retain its classesN.dex filename and sign the APK with your usual keystore.
The MainActivity hook, index.html and currently working encrypted payload require no change for this update.

ADD YOUR LOGOS IN THE GAME APK
Create this folder inside the GAME APK:
assets/royal_void/images/themes/
Add eight PNG files named:
dark.png
fire.png
thunder.png
water.png
earth.png
diamond.png
gold.png
spirit.png

Use transparent square PNGs with the same Gojo + DG composition, consistent padding, and theme-specific colours.
You can also place these files under the source project's assets/royal_void/images/themes/ for safekeeping.
The DEX build does not copy them into your target game APK; add them with MT Manager.
Missing or unreadable theme images use assets/royal_void/images/brand_logo.png.
Logo files have not been generated by this update; until you add them the eight themes share the existing logo.
Artwork and item pictures retain their original colours.

OPTIONAL SERVER CONTROL
Deploy the complete replacement server/dg-worker.js to the EXISTING dg Worker.
Keep existing DG, DG_R2 and all secrets/bindings. Do not create another Worker.
This adds themes to the existing /check response and combines DexBranding + DexThemes into one Supabase read.
It does not upload, encrypt or replace the currently working game payload.
Without the Worker update, all eight built-in themes still work locally; owner overrides will not arrive.

Website main branch: /admin-control -> Royal Void DEX -> Royal Void themes.
Enable/disable themes, select the default, and optionally enter palette overrides.
At least one theme must remain enabled. Checked here means AVAILABLE; this differs from feature-lock checkboxes.
Save DEX themes. Changes apply at the next game launch.
Existing users keep their explicit selected theme if still enabled; otherwise the configured default is used.
Owner defaults apply when no local theme has been chosen.
Palette overrides with unreadable text fall back to the built-in palette.

Storage: existing app_config table, row id DexThemes, data JSON object:
{
  "schema": 1,
  "defaultTheme": "dark",
  "enabledThemes": ["dark","fire","thunder","water","earth","diamond","gold","spirit"],
  "palettes": {}
}
Optional palettes: {"fire":{"primary":"#F97316","deep":"#7F1D1D","highlight":"#FFBA88"}}
Other override keys: background, panel, card, text, muted, border, input, success, error.
Only #RRGGBB colours and the eight known theme IDs are accepted.
Palettes are appearance data; they contain no executable scripts or private keys.
Server overrides use the HTTPS startup configuration; they are not signed game payload updates.

CHECK AFTER INSTALLING
1. Finish existing login and open Command centre.
2. Select Fire, Water, Gold and another theme; check launcher, header, cards, controls and dialogs.
3. Close/reopen the game: your choice should remain.
4. Export/import settings: the theme should restore if still enabled by the owner.
5. Open inventory and gameplay pages: existing controls should still work.
6. With owner control deployed, disable one selected theme and restart to verify fallback.
