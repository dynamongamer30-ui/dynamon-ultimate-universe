Single preparation action:
1. Install this update over the existing microG probe. Existing virtual game/account data retained.
2. Tap Prepare & sign in. It validates/imports the installed original game in place,
   validates/reuses official microG and opens its official LoginActivity.
3. Continue through microG's Sign in UI. After completing account login, launch the game
   using Run full startup test and use its Google sign-in/profile flow.
The original outside-container account session is not copied. No tokens/passwords are
handled by this launcher. Initial runtime download is required only if verified files are absent.
The separate old BlackBox probe and phone's Google apps/accounts are not replaced.

Consolidated changes:
- Connectivity proxy now forwards real platform responses and exceptions. Removes fabricated
  connected Wi-Fi, synthetic network identifiers/DNS and forced internet-validation flags.
- AppOps preserves actual method return types, including modern object returns, and genuine
  permission denials. Translates only the caller identity to the host's real OS identity.
- Activity-manager failures propagate without a second invocation or fabricated success result.
- Preserves all content-provider authorities/aliases. Failure to register a required microG
  provider is reported as a failure rather than silently returning an empty result.
- Account visibility changes are persisted; authenticator ownership, explicit user decisions
  and user-managed visibility are recognized. Null account type means all types within
  the requested profile. All-account queries no longer aggregate unrelated virtual profiles.
- Existing dual-layout activity launch, service callback, installed-authenticator discovery,
  provider caller/payload preservation and original split-byte validation remain present.
- HTTPS endpoint probes are bounded and run off the login-launch path. They use fixed
  anonymous HEAD requests, reporting only numeric HTTP status or exception class.
  An HTTP response is transport reachability, never check-in/authentication success.
- Readiness records separate authenticator/account/check-in presence booleans and the original
  game's GoogleApiAvailability numeric result. No account name, token or device ID is recorded.
- Retains bounded login WebView metadata/main-thread/check-in-stack and ANR-frame observations;
  never reads page content, cookies, passwords or account fields into the report.

Official microG service compatibility:
The prior probes imported replacement services without implementing their documented
service-signature compatibility requirement. This update implements a guest-only view
for TWO exact, hash-verified upstream APKs. It uses the public compatibility certificate
already declared by those upstream APKs. Their actual APK signing bytes are not modified.
Legacy signatures, modern SigningInfo, certificate queries and the virtual compatibility
permission are handled for these packages only. Other packages, including Dynamons,
retain their actual signing metadata. No OS privileged permission or server authorization
is granted. Host import verification continues reporting real archive identity/bytes.
Unsupported runtime versions, changed bytes, wrong package names or sizes are rejected.
