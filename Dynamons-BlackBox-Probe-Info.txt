The user confirmed that probe 0.2.1 loaded the game and gameplay worked without
crashing on Android 16 / ARM64. Its report showed a complete WebView document,
Lime, Cordova and a render canvas. This observation does not verify Google login,
other devices or this updated build. Google authentication remains untested.

New in 0.2.2:
- Adds Set up installed Google services, importing installed phone APKs for user 0.
- Required dependency set: Google Services Framework, Google Play services, Play Store.
- Optional dependencies: legacy Google login package and Google Play Games, if installed.
- Validates actual package/version metadata, base APK and all split APK SHA-256 bytes.
- Reuses matching imports; refreshes mismatched imports in place without uninstalling.
- Reports missing packages and partial failures, retaining existing imports and data.
- Stops only the guest game before setup so its next launch resolves new dependencies.
- Removed GmsProxy, GoogleAccountManagerProxy and AuthenticationProxy, including their
  mock accounts/tokens and fabricated login-success fallbacks, and their registrations.
- No microG bundle, external downloads, Google account/session transfer, or token copying.
- No certificate impersonation, server authentication bypass or successful-login claim.

Retained:
- Modern three-argument, one-way IServiceConnection callback and raw Binder relay.
- Local on-device relay check before launch, 45-second launch cooldown.
- Original game imports without rebuilding/re-signing the original base or splits.
- ARM64 Dobby/xDL native engine with 16 KB ELF load alignment; no Pine/SpaceCore.
- Disabled external log transport and logcat harvesting; reports shared only by user action.
- Separate container game/account data. No mod-menu attachment or save transfer yet.
- Host permissions remain network, audio settings, vibrate, wake lock and foreground service.
  No additional account, overlay, all-files, camera or microphone permission request.

Test on phone:
1. Update the existing BlackBox probe with this APK; do not uninstall it or the game.
2. Tap Import installed original game.
3. Tap Set up installed Google services and read each package result.
4. Tap Run full startup test, then use the game's own Google sign-in button.
5. Confirm your actual profile/progress, then reopen the game to check persistence.
6. If sign-in fails, return to the probe and Share startup report; include any visible
   sign-in error code. Do not share passwords, account tokens or login response bundles.
If Play Games is requested, install the official app on the phone, then repeat setup.
Dependency imports alone cannot establish server authentication or leaderboard writes.
Modern system Google packages may require OS integration that a container cannot supply;
that compatibility remains to be tested on this device.

Build prerequisites:
JDK 17+, Gradle 8.9, Android platform 35, Build Tools 35.0.0,
NDK 29.0.13846066-beta3. Host Android 8/API 26+.
Create local.properties with sdk.dir pointing to your SDK, then run build_debug.sh.
The script generates a development signing key locally; no private key is delivered.

Validation:
Gradle debug build, APK signature/version/permission/ARM64 checks, ZIP consistency,
11 split-import validation checks and 8 crash-frame filtering checks.
Actual Google login and Arena server writes are not verified.
