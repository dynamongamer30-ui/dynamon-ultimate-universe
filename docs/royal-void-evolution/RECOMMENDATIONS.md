## Phase 18 — recommendation query and account-state reliability (24 October 2026)

ForYouRail performed its own likes/favorites reads alongside the shared collection hooks used by home cards. Its effect depended on whole user/catalog objects, treated failed requests as empty results and kept prior account affinity/loaded state until a new read completed. None of its reads had cancellation/deadline handling.

The rail now consumes the existing shared favorites/likes queries and an account-ID-keyed recommendation-elements query. The preferences query has a ten-second deadline, forwards cancellation, disables SDK/query retries and focus refetch, and discards inactive cached data immediately. Ranking still uses the existing element-match/download formula with at most four picks; only known element keys contribute to affinity. Derived affinity follows current catalog/shared collection data without a repeated read effect. Unknown keys and duplicates are excluded. No preference write, new backend, migration or authorization change is introduced.

The named region has explicit loading/pending, failure/retry and ready states. A failed source cannot produce fallback personal picks; Retry requests only failed sources. Pending collection mutations temporarily withhold recommendations, so an optimistic/rolled-back favorite is not presented as confirmed affinity. An account with no known affinity produces no invented personal rail. Account-ID query keys and cancellation prevent the previous user's affinity/late responses from appearing after account switch/sign-out. The shared hook exposes existing fetch state without changing its read/write logic. Recommendation links receive a single accessible mod name rather than repeated image/text names.
