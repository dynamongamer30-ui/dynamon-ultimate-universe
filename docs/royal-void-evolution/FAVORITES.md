# Favorites reliability — 24 October 2026


The shared collection hook previously accepted an error-free response as proof of a favorite change. A zero-row write could therefore produce success/XP or an empty vault without confirmation. Bookmark controls stayed active while saving, collection reads had no deadline, and a late result could produce success feedback after sign-out.

Favorite inserts/deletes now request only the changed mod_slug. An insert requires a matching returned row. A zero-row delete performs one bounded, current-user/current-slug absence check before success; a remaining row or failed read rolls back. The last-card removal shows Updating your vault until confirmation instead of a premature empty-vault message. Shared TanStack mutation state disables the affected bookmark across mounted consumers/navigation, while the existing synchronous per-client/per-user/per-slug lock prevents duplicate requests. Different-card rollback remains isolated. Current identity and original query-object checks suppress stale completion/XP feedback and prevent disposed account cache resurrection.

Both saved-collection reads now honor TanStack cancellation, have a ten-second deadline and disable SDK retries. Collection writes also have a ten-second deadline with retries disabled. Existing like request/response semantics remain; favorites alone require changed-row proof. Likes share the cancellation/deadline/account-generation safeguards. No grant, policy, reward definition, Worker/native protocol or production record was changed. Timeout ambiguity can still mean a server committed a request before the client lost its response; the UI does not promise rollback of server state.

Validation: all 40 local browser checks pass in 3.5 minutes across Chrome phone/tablet/desktop and WebKit: seven favorites cases, two existing account-cache cases and one public favorites/bookmark journey per project. This includes pending navigation deduplication, confirmed insert before XP, zero-row add/remove recovery, failure isolation between two cards, late completion after sign-out, stalled-read timeout/retry and signed-out privacy/redirect checks across four widths. All 31 Node tests pass, including a separate local policy fixture; TypeScript/build pass. Final lint/rollout follow.
