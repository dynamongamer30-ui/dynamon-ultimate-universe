# Mod delivery rules

Keep complete files byte-for-byte unless an explicitly requested change requires editing them. Never omit code, abbreviate a file, insert placeholder sections or silently truncate output.

Latest user preference: openable GitHub file links for individual source files instead of very long chat code blocks. Use GitHub ZIP links for larger sets and preserve source/asset folder structure. Include only needed files, rather than making the user manually place many files in different directories. Do not use ChatGPT download attachments.

Previous index.html preference was copyable content rather than a browser-rendered HTML attachment; latest clarification prefers file viewers/save menus for long files. Provide the full source through GitHub's file view, never an HTML chat attachment.

Sync authorized future mod deliverables to royal-void-downloads-20261009. Keep main unchanged unless the user explicitly requests/authorizes a main change. Keep main and the download branch; the user authorized removal of other branches. Do not claim branch deletion until verified.

After EVERY completed mod task, update MOD_SYSTEM_GUIDE.md: remove false/superseded details, fill verified gaps, and describe current behavior precisely. Maintain the detailed handover (approximately the previous 80 KB guide), with accuracy taking priority over exact byte count. Separate prepared source, compiled DEX, installed APK, live payload and in-device validation. Do not call a source-only repair live.

Sync the guide, complete changed files, relevant archives, entrypoint links and checksums to the download branch as part of task completion. Clean superseded files only after retaining necessary source/assets and correcting dependent links/workflows. Compare/verify the branch head and written files. This is the assistant's standing post-task workflow, not a separate background automation service.

MOD_SYSTEM_GUIDE.md at the branch root is authoritative; raw-project/MOD_SYSTEM_GUIDE.md points to it to prevent contradictory copies. Follow AGENTS.md for the same standing workflow.
